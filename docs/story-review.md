# A second look before sending

Obvious repeated filler and three explicit prompt-comment phrases open a local reminder. It shows the exact draft, the story's instruction and, for an ending, the caught beginning. Keep editing, Escape and closing retain the draft without consuming a check. A deliberate **Send these words anyway** uses the existing setup/reply request with the same words, round and ordinary safety checks.

The choice is bound to the draft key, text, round, stage, assignment and lease version. A changed assignment cancels it. Expiry, unavailable beginnings, exhausted checks, pauses and human verification still prevent sending. The server accepts no new override flag, role or endpoint. A refused check keeps the draft editable.

This is a limited deterministic reminder, not semantic moderation or a claim to recognize trolls. It does not judge intent, humor or whether every creative answer fits a prompt. Writers can deliberately keep repetition or unconventional jokes. The reminder runs in the browser and makes no provider call; normal submission still uses the existing moderation path. It is not bot protection or a replacement for server rate limits, verification and reporting.

Five new unit checks cover filler, punctuation/case, known prompt comments, ordinary absurdity, validation boundaries and approval binding. Seven Chrome/WebKit cases cover a real keyless two-writer flow, free review/editing, narrow-screen accessibility, a real local pause, an injected version change, an injected safety denial and deliberate submission. The refusal fixture tests that the UI respects an error; it does not measure a live model's decisions. No new paid evaluation, production story or physical-phone evidence.
