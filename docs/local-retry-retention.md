# Bounded local retry text

A transport exception could leave a `drift:request:*` record containing submitted text and its request ID indefinitely. Drafts already had a seven-day envelope, but request records did not. Retry records now use that same envelope. Startup/reconnect and the existing one-minute maintenance tick prune expired draft/request text across identities, including the memory fallback when browser storage is unavailable. Reads enforce the exact expiry even before the next tick. Closed browsers perform cleanup on the next visit; no background execution while the page is closed is implied.

Before expiry, identical text reuses its original request ID. Unknown transport outcomes keep that record; a confirmed result removes both the memory and local-storage record immediately. A new attempt renews the seven-day expiry. Legacy records have no creation time, so first access migrates them with a seven-day limit while retaining the existing ID; no invented historical timestamp is claimed. Malformed cached IDs cannot enter the SDK's paid-call arguments. The existing server request bindings, quotas and cost reservation remain authoritative and unchanged.

Manual reconnect now immediately clears the connected flag, and callbacks from replaced SDK connections cannot mark the replacement ready or overwrite its state. Readiness becomes true when the current active connection's subscription applies.

Six Chrome and six WebKit checks pass through `npm run test:retention` / `DRIFT_TEST_ENGINE=webkit npm run test:retention`. The test injects a lost response **after an actual local server commit**, reloads the browser, replays the same request and reads the owner's local request table: there is exactly one request, and its ID is unchanged. It also checks legacy migration, malformed IDs, startup cleanup across inactive identities, the exact expiry boundary and memory-only expiry with unavailable storage. All words/identities are synthetic and the local model provider is disabled. This is not a hosted network fault or billing test.

The test exposed an incorrect test wait: in this Playwright version the predicate loop treats a returned Promise as truthy, so putting a dynamic import inside `waitForFunction` can finish with a false value instead of polling. The current letter, ritual and retention suites now import the test game first and poll synchronous booleans. No arbitrary sleep was added to make the failure disappear. The older historical browser scripts have not all been migrated and are not current release gates.

This closes a concrete privacy/reliability gap for the People-First product case and preserves the request-ID boundary protecting Claude spend. It does not add a sponsor service or establish eligibility, moderation quality or attendee outcomes.
